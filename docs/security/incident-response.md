作成日: 2026-11-16。参照: [Security Standard](security-standard.md) / [Security Review](../workflows/security-review.md) / [Privacy Policy Standard](../legal/privacy-policy-standard.md)。

> **ここに記した期限は法定期限ではありません。** 個人情報漏えい等に該当する場合、個人情報保護委員会への報告・本人通知などの要否と期限を適用法令に従い個別判断。事実未確認のまま「漏えいなし」と断言しない。

## IR-01 検知と一次判定
- Cloudflareログ/アラート、GitHub Advisory/Secret scan、Google/音楽API側の通知、利用者報告を受け付ける。
- 何が起きたか、最初の検知日時、影響URL/アカウント、兆候、未確認事項、担当者を記録。ログと証拠の閲覧/保存権限を制限。
- 深刻度は実被害・機微情報・悪用の容易さ・公開範囲等から評価。未確認を隠さない。

## IR-02 被害の封じ込め
- 流出した可能性のあるCloudflare/GitHub/Google/OAuth/API秘密情報を**失効/再発行**。値の変更だけで旧権限が有効なままにならないか確認。
- 必要に応じAPI/機能を一時停止し、WAFルールやレート制限で悪用を緩和。ただし正規利用への影響を評価。
- R2の誤公開を停止し、CDNキャッシュ、Presigned URL、`r2.dev`経由の漏出経路を確認。
- React RSC/Vinextの既知脆弱性なら依存修正・安全なビルド/デプロイを優先。**WAFだけで恒久対処済みとしない**。

## IR-03 調査・復旧
- 悪用の有無、ログ/保存データ、権限変更、署名URL、Git履歴/Actions、DB更新/削除を検証。
- 最小限の機密ログを保全し、監査証拠の誤消去を避ける。利用者情報の無関係な共有は禁止。
- 修正PRと検証結果を保存。Preview/本番相当で再現試験と否定試験を行い、責任者が復旧を承認。
- D1のバックアップ/リストア、R2の復旧、Cloudflareデプロイのロールバックを**事前検証した手順**で実施。ロールバック先に脆弱性が残っていないか確認。

## IR-04 連絡・事後対応
- 事業者の個人情報取扱いと法令に照らして監督機関・本人・関係者への報告/通知要否、期限、内容を判断。
- 開示する事実、推測、利用者が取れる措置を分けたコミュニケーションを作成。
- 根本原因、検知までの時間、権限、手順/CI/監視の改善を振り返り、SEC-01〜SEC-36・脅威モデル・プライバシー台帳を改訂。
