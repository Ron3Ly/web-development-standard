# Design Page
1. Read `AGENTS.md`, `docs/design/ui-guidelines.md`, `docs/design/design-system.md`, `docs/design/ui-references.md`, `docs/design/ui-assets.md`, and the project brief.
2. State target users, goals, content, constraints and accessibility requirements.
3. Propose information hierarchy, page sections, reusable component inventory and responsive behavior.
4. Identify which of the six UI/UX guidelines apply and why. Use WCAG 2.2 AA as the common accessibility target and APG for advanced interactions. For Japanese UI prioritize relevant Digital Agency guidance; use Windows Design and IBM Carbon patterns only where appropriate.
5. Name the relevant design reference principles and asset candidates; flag license checks. Consider Astryx components/templates as an **optional** implementation candidate and consult `docs/design/astryx.md` before suggesting it.
6. Record assumptions, project-specific overrides and open questions.
7. Produce a concise design specification suitable for implementation.

Do not copy protected visual assets or adopt an unrelated technology stack.
