# Game Assets — Licensed 2D Source Selection

1. Read `AGENTS.md`, `docs/game-assets/README.md`, `docs/game-assets/licensing.md`, `docs/game-assets/asset-register.template.md`, `docs/game-assets/web-implementation.md`, `docs/workflows/game-asset-review.md`, and the active project's brief.
2. Identify 2D game genre, visual style (pixel/vector), platform/browser targets, icon/UI categories, SFX/BGM needs, VFX intensity, commercial/ads/paid use, and the actual distribution model (public web game, source repo, R2/CDN).
3. Prefer verified CC0 sources (e.g., individual Kenney packs) when possible. For Game-icons.net, record **each actual author** and CC BY 3.0 attribution; OpenGameArt/Freesound/itch.io require per-file checks. Mixkit Free SFX ≠ Mixkit Stock Music (the latter does **not** permit video games).
4. Read the actual source item's official license and keep a per-file asset record: title, creator, source page, license and version, modification, target file path, production delivery method, credits and reviewer/date. Do not infer that free download grants unconditional redistribution rights.
5. Evaluate custom licenses: Mixkit cannot be redistributed as standalone/source material; Sonniss GDC permits game projects but prohibits selling original sounds or AI/ML training. If browser-served raw files or public GitHub/R2 expose licensed material in a prohibited manner, **hold the asset pending permission**.
6. Create a Credits page or menu entry with the exact attribution for CC BY/other licenses. Preserve source/credit records even for CC0. Don't copy source packs or licensed audio into this shared standards repository.
7. For a real app, test user-gesture audio unlock, volume/mute, alternative feedback, browser codecs, sprite scaling, performance, reduced motion, and WCAG 2.3.1 flash limits. Secure untrusted SVGs, respect Cloudflare R2 distribution rules and avoid using Spotify/Apple Music API access as BGM rights.
8. Complete GAME-01–GAME-24 with Pass/Fail/Not tested/Not applicable/Needs permission, evidence, and risk owner. Do not certify licensing/compliance without inspection or claim untested UI/audio passed.
9. Produce a suggested, minimal project-specific asset set with source links, license caveats, credits, performance and browser test plan. Ask for owner approval before publishing or rehosting restricted material.

This skill performs asset research and design integration, **not copyright clearance or acquisition of blanket redistribution rights**.
